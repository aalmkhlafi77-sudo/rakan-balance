# RAKAN BALANCE — المرحلة B: التخزين المركزي المقيد بالإصدار

**الحالة: أساس للخادم فقط؛ غير مكتمل أو قابل للنشر للجمهور.**

يتبع هذا الفرع المرحلة A (PR #27) ولا يغير واجهة التطبيق الحالية أو تخزين بيانات الزوار.

## ما نُفذ

1. جدول MySQL مستقل `owner_ledger_snapshot` في `database/002_owner_ledger_snapshot.sql`.
2. استرجاع البيانات على `GET /api/owner/ledger` بعد تسجيل دخول المالك فقط.
3. حفظ البيانات على `PUT /api/owner/ledger` مع Cookie جلسة الخادم و`Origin` و`X-CSRF-Token` ورقم إصدار متوقع `expectedRevision`.
4. التحقق على الخادم من نسخة `BackupBundle` بواسطة **المُدقّق المالي القائم نفسه** الذي يتحقق من المبالغ، الحسابات، المراجع، الأطراف المتقابلة، والتخصيصات.
5. تنفيذ الحفظ داخل معاملة MySQL مع قفل صف `FOR UPDATE`، وإرجاع HTTP 409 إذا حفظ جهاز آخر نسخة أحدث.
6. بصمة SHA-256 محفوظة مع محتوى السجل ويجري التحقق منها قبل قراءة البيانات.
7. اختبارات HTTP لعزل بيانات المالك، وCSRF، وصحة بنية البيانات، والتعارض بين الإصدارات.

## قيود تمنع النشر حاليًا

- **لم تُربط واجهة المستخدم بقاعدة MySQL.** الواجهة الحالية تحفظ البيانات في IndexedDB. لا يصح تقديمها بوصفها واجهة مالك متزامنة.
- **ملفات المرفقات داخل Bundle** عبر dataUrl تجعل إعادة إرسال الحالة كاملة غير ملائمة للمرفقات الكبيرة. يلزم مستودع ملفات خاص، حماية تنزيل، حدود أحجام وتوافق تام مع الاستعادة قبل اعتمادها للإنتاج.
- لا تتوفر حاليًا بيانات دخول Hostinger أو قاعدة MySQL تجريبية لاختبار المعاملات الفعلية واستقرار اتصال الخادم.
- المصادقة والحفظ يحتاجان اختبارات اختراق واعتماد إعدادات جلسات/محدّد محاولات دائم قبل التشغيل العام.
- لا ينبغي تمكين التشغيل دون إنترنت في مساحة المالك حتى تُثبت سلامة طابور التغييرات والتعارضات.

## ترتيب الاستكمال المعتمد

1. **المرحلة C**: شاشة دخول/خروج المالك واختيار وضع محلي للزائر؛ مالك واحد فقط بلا تسجيل عام.
2. **المرحلة D**: واجهة تخزين خاصة بالخادم لجميع عمليات الحسابات والحركات والاستحقاقات والتخصيصات والملاحظات والمرفقات دون الكتابة إلى IndexedDB عند الدخول كمالك.
3. **المرحلة E**: تنظيف وضع المعاينة من الإنتاج (PR #29) وضمان بقاء اختبارات المتصفح منفصلة؛ لا حذف للمخازن المحلية التاريخية.
4. **المرحلة F**: استيراد نسخة احتياطية إلى مساحة المالك بعد فحصها، وإثبات المزامنة على جهازين، ومنع ضياع التعديلات/تكرار القيود.
5. **المرحلة G**: إعداد Hostinger Business على `rakan.carpetbazar.org` في موقع مستقل، مع SSL ومفاتيح الخادم الخاصة ونسخ احتياطية لقاعدة MySQL.

لا تضع أي كلمة مرور أو مفتاح API أو بيانات مالية حقيقية في GitHub أو ملفات اختبار المشروع.
