# راكان بلانس | RAKAN BALANCE — خطة التنفيذ الهندسية والتأسيسية النهائية (N0)

نواة تطبيق ويب مستقل ودقيق لإدارة الذمم الشخصية والمالية وفق وثيقة العمل الهندسية v2 (Blueprint v2)، بمبدأ المالك الواحد والعملة المحلية الموحدة (ريال سعودي SAR)، مع فصل كامل ومستقل للمنطق المالي عن وسائط التخزين والعرض، وتخزين الأموال بأعداد صحيحة بدقة الهللة.

| :--- | :--- | :--- |

## 1. ضبط الملاحظات الهندسية الثلاث المتبقية

### 1.1 استراتيجية النقل إلى Flutter / Dart وضبط التوقعات
- **الواقع الهندسي**: تطبيق الويب الحي يُبنى في بيئة Google AI Studio الحالية باستخدام تقنيات الويب القياسية (TypeScript + Vite + React 19). الانتقال المستقبلي إلى Flutter / Dart على أجهزة الهاتف ليس تحويلاً آلياً كود-بكود.
- **الحل المعتمد**:
  1. صياغة القواعد والمعادلات المالية في طبقة **Domain** نقية وخالية تماماً من أي اعتماديات على المتصفح أو أطر العرض أو المكتبات الخارجية (`Pure TypeScript Domain`).
  2. توثيق العقد المالي والمعادلات الرياضية بصيغة مواصفات خوارزمية قياسية واضحة (`Specification & Test Invariants`) مع حالات اختبار موحدة ومستقلة، بحيث يتمكن المهندس لاحقاً من إعادة كتابة واختبار نفس المنطق في Dart لمشروع Flutter بنفس المدخلات والمخرجات دون أي غموض أو تباين في النتائج.

### 1.2 العزل الهيكلي للبيانات التجريبية (Demo Workspace Isolation)
- **منع الاختلاط التام**: لا يُكتفى بحقل علامة `isDemo` فقط؛ بل تُعزل البيانات التجريبية في **نطاق تشغيلي ومساحة تخزين مستقلة** داخل قاعدة البيانات (`demo_accounts`, `demo_transactions` أو بادئة نطاق منفصلة تماماً `demo_scope`).
- **قواعد منع العلاقات الهجينة (Zero Cross-Contamination)**:
  - يُمنع برمجياً وفي طبقة التحقق إنشاء أي حركة حقيقية ترتبط بحساب تجريبي.
  - يُمنع إنشاء أي حركة تجريبية ترتبط بحساب حقيقي.
  - لا تدخل الحسابات التجريبية إطلاقاً في حسابات لوحة التحكم الحقيقية أو التقارير الرسمية، إلا عند تفعيل «وضع المعاينة التجريبية» الذي يفتح النطاق التجريبي بشكل منفصل ومرئي ومميز بلون شريط تحذيري.
- **حماية التصفير**: دالة `purgeDemoData()` تستهدف حصراً مساحة النطاق التجريبي دون إمكانية الوصول إلى مخازن البيانات الحقيقية برمجياً.

### 1.3 الاستعادة الذرية الصارمة (Atomic All-or-Nothing Restore)
- **مراحل تدفق الاستعادة**:
  1. **مرحلة التحقق والاستعداد (Staging & Validation)**: فك حزمة النسخة، فحص صحة المخطط (`schemaVersion`)، والتحقق التشفيري من تجزئات SHA-256 لجميع السجلات ومرفقات الـ BLOBs، والتأكد من مطابقة الأعداد.
  2. **نقطة الرجوع الاحتياطية (Safety Snapshot)**: أخذ لقطة سريعة للبيانات الحالية وحفظها في مخزن استرجاع مؤقت قبل لمس الجداول.
  3. **الاستبدال الذري في معاملة واحدة (Single Atomic Transaction)**: فتح معاملة IndexedDB واحدة تشمل جميع المخازن معاً:
     `db.transaction(['accounts', 'transactions', 'categories', 'attachments', 'settings'], 'readwrite')`
     يتم تفريغ الجداول القديمة وكتابة السجلات الجديدة والمرفقات ضمن نفس المعاملة. في حال فشل أو حدوث استثناء في أي سجل أو مرفق، تقوم المعاملة بإلغاء التغييرات تلقائياً (`transaction.abort()`) مع بقاء الحالة السابقة كما هي دون أي تجزؤ أو تلف نصفي.

## 2. العقد المالي الإلزامي والمعادلات المعتمدة

منظور الإشارة ثابت من طرف مالك التطبيق:

| الحركة | النوع البرمجي | الإشارة والقيمة | الأثر على الرصيد $B$ |
| :--- | :--- | :--- | :--- |
| **مبلغ عليه** | `owedByAccount` | $+ \text{amountMinor}$ | **يزيد الرصيد** (دين لك في ذمته) |
| **مبلغ له** | `owedToAccount` | $- \text{amountMinor}$ | **ينقص الرصيد** (التزام عليك لصالحه) |
| **سداد / دفعة** | حركة عكسية واحدة | $+ \text{amountMinor}$ أو $- \text{amountMinor}$ | **حركة مالية واحدة فقط**؛ والتخصيص المستقبلي مجرد بيان متابعة |

- **المبالغ بالهللة**: تخزين الأرقام كأعداد صحيحة موجبة للحركة (`amountMinor > 0`)، والرصيد الافتتاحي موقع (`openingBalanceMinor`).
- **معادلة رصيد الحساب**:
  $$B(\text{account}) = \text{openingBalanceMinor} + \sum \text{signedTransactionsMinor}$$
  - $B > 0$: **لك** (رصيد موجب يطالب به المالك).
  - $B < 0$: **عليك** (رصيد سالب يلتزم به المالك للطرف الآخر).
  - $B = 0$: **متوازن**.
- **معادلات لوحة التحكم**:
  - إجمالي لك = $\sum \max(B, 0)$ عبر الحسابات النشطة.
  - إجمالي عليك = $\sum \max(-B, 0)$ عبر الحسابات النشطة.
  - صافي المركز = إجمالي لك $-$ إجمالي عليك = مجموع الأرصدة الموقعة.
- **رصيد أول وآخر الفترة لكشف الحساب**:
  - رصيد أول المدة ($B_{\text{start}}$) = الرصيد الافتتاحي + مجموع الحركات السابقة للفترة ($\text{date} < \text{fromDate}$).
  - رصيد آخر المدة ($B_{\text{end}}$) = $B_{\text{start}}$ + مجموع حركات الفترة المحددة ($\text{fromDate} \le \text{date} \le \text{toDate}$).
  - قاعدة الفرز المستقر الإلزامي: التاريخ ($\text{date}$) $\rightarrow$ وقت الإنشاء ($\text{createdAt}$) $\rightarrow$ المعرف الفريد ($\text{id}$).

### التحقق من تسلسل المثال المرجعي الإلزامي:
- افتتاح: `+200`
- عليه: `+150` $\rightarrow$ الرصيد: `+350`
- له: `-80` $\rightarrow$ الرصيد: `+270`
- له: `-300` $\rightarrow$ الرصيد: `-30`
- **النتيجة**: الرصيد النهائي `30` ريال عليك (`-30.00`). الرصيد قبل الحركة الأخيرة `270` ريال لك (`+270.00`). وكشف حساب يبدأ من الحركة الأخيرة يفتتح برصيد `+270.00` حتماً.

## 4. عقود النماذج ومواضع التوسعة المستقبلية (Data Contracts & Future Seams)

### النماذج التنفيذية الحقيقية في N0:
- **Account**:
  `{ id, name, parentId: string|null, categoryId, openingBalanceMinor: int, status: 'active'|'archived', phone?: string, notes?: string, createdAt, updatedAt }`
- **Category**:
  `{ id, name, sortOrder: number }`
- **Transaction**:
  `{ id, accountId, entryType: 'owedByAccount'|'owedToAccount', amountMinor: int (>0), date: 'YYYY-MM-DD', description, notes?: string, attachmentIds: string[], createdAt, updatedAt }`
- **Attachment**:
  `{ id, transactionId, originalName, mimeType, size: number, dataBlob: string, createdAt }`
- **BackupManifest**:
  `{ schemaVersion: 2, generatedAt, checksums: { data: string, attachments: string }, counts: { accounts: number, transactions: number, attachments: number } }`

### عقود ومواضع التوسعة المحجوزة للمستقبل (N1/N2 Seams - بدون واجهات فارغة):
```typescript
// Contract for future DueItem (Section 15 in Blueprint v2)
export interface DueItemContract {
  id: string;
  accountId: string;
  sourceTransactionId?: string;
  dueDate: string;
  originalAmountMinor: number;
  settledAmountMinor: number;
  status: 'pending' | 'partially_settled' | 'settled' | 'overdue';
}

// Contract for future PaymentAllocation (Section 15 in Blueprint v2)
export interface PaymentAllocationContract {
  id: string;
  dueItemId: string;
  paymentTransactionId: string;
  amountMinor: number;
}

// Contract for future Reminder (Section 15 in Blueprint v2)
export interface ReminderContract {
  id: string;
  dueItemId: string;
  remindAt: string;
  templateText: string;
  isCompleted: boolean;
}
```

## 5. مصفوفة التحقق والاختبارات الآلية الستة الإلزامية

| # | الاختبار | السيناريو والقيم | معيار النجاح الصارم |
| :--- | :--- | :--- | :--- |
| **1** | **المثال المرجعي (وثيقة v2 - بند 4.1)** | رصيد افتتاحي `+200`، عليه `+150`، له `-80`، له `-300` | الرصيد النهائي `-30.00` (عليك). رصيد بداية كشف حساب يبدأ بالحركة الأخيرة يساوي `+270.00` حتماً. |
| **2** | **تطابق الإجماليات واللوحة** | حساب أ: `+100`، ب: `-70`، ج: `+20` | إجمالي لك = `120`، عليك = `70`، الصافي = `50`. تطابق تام لا يحتمل خطأ هللة واحدة مع كشف الحساب. |
| **3** | **استقلال الحسابات الفرعية** | حساب أب تحته حسابات فرعية بحركات منفصلة | احتساب رصيد كل حساب من حركاته فقط دون مضاعفة رصيد الأب والأبناء في إجمالي المركز المالي العام. |
| **4** | **الذرية المطلقة للاستعادة** | محاكاة استعادة ملف تالف أو تعمد قطع المعاملة أثناء الكتابة | فشل المعاملة وإلغاؤها بالكامل (`transaction.abort()`) مع بقاء البيانات السابقة سليمة بنسبة 100% دون أي تلف جزئي. |
| **5** | **العزل الهيكلي للبيانات التجريبية** | إدخال بيانات حقيقية ثم تفعيل/تصفير النطاق التجريبي | منع أي ربط بين حساب حقيقي وحركة تجريبية، والتأكد من أن تصفير التجربة لا يمس أي سجل حقيقي. |
| **6** | **منع الدورات في شجرة الحسابات** | محاولة تعيين حساب كأب لنفسه أو لأحد فروعه | اكتشاف الحلقة فوراً ورفض العملية مع رسالة واضحة للمستخدم. |

## 6. خطوات تسليم المرحلة وإجراءات النشر

1. **الالتزام الكامل بحدود البيئة**: لا يتم إنشاء مستودع GitHub أو فروع أو طلبات دمج (PRs) من قِبل المساعد.
2. **تسليم الكود المستقل**: بعد نجاح بناء واختبار التطبيق الحي بكافة شروطه، يتم تجهيز حزمة الملفات بالكامل لتمكين المالك من رفعها يدوياً إلى المستودع الجديد في فرع `main`.
3. **توفير مواصفات واختبارات القواعد لـ Dart**: توثيق ملفات اختبارات مستقلة ومواصفات خوارزمية دقيقة تسهل بناء مشروع Flutter المقابل لاحقاً.
